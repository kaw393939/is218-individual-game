# Research roadmap

<span class="status-pill">Current phase · Research & planning</span>

This sequence defines the work before game implementation. It is not a promise of delivery dates. The documentation site is the initial completed deliverable.

## 01 · Establish the research notebook

- [x] Create a VitePress documentation site.
- [x] Establish a dated initial research snapshot and primary-source library.
- [x] Draft an engine shortlist, workflow, and experiment backlog.

**Output:** a shared place to collect evidence and decisions.

## 02 · Define the smallest useful game

- [ ] Complete the [game brief](./game-brief.md).
- [ ] Choose a target player, device, and delivery platform.
- [ ] Agree on one core loop and a small first-playable scope.
- [ ] Set the time and asset budget.

**Output:** a clear concept with explicit exclusions and observable success criteria.

## 03 · Compare approaches

- [ ] Run the planning-only engine comparison, E01.
- [ ] Review the design document with an assistant, E04.
- [ ] Define an asset brief and provenance convention.
- [ ] Decide whether runtime AI has a concrete player benefit.
- [ ] Record the engine, assistant workflow, and asset approach in the [decision log](./decisions.md).

**Output:** evidence supporting a feasible approach; unresolved questions stay visible.

## 04 · Prepare the implementation handoff

- [ ] Write the first playable milestone and acceptance criteria.
- [ ] Define how to run, inspect, and export the future game.
- [ ] Choose a small set of meaningful behavior checks and playtest questions.
- [ ] Identify the implementation task that should happen first.

**Planning exit criteria:** target platform, engine, core action, win/fail loop, asset approach, time budget, and initial acceptance criteria are recorded. The user then chooses to begin game coding.

## Later · Build, playtest, and revise

Implementation, asset trials, and playable prototypes belong to the next phase. [E02 and E03](./experiments.md) are prepared for that phase, with no results recorded yet.

Future milestones should favor a complete loop—start, play, feedback, ending, restart—before adding more content. That is a proposed scope choice to revisit after the first playtest.
